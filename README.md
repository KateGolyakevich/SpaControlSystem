## 📋 Описание проекта

Программная система **«AuraSPA»** предназначена для автоматизации работы администратора СПА-комплекса. Программа решает задачи комплексного расписания, складского учета и управления клиентами с гарантией отсутствия накладок на ресурсы салона.

### 🌟 Ключевые возможности:
* **Управление клиентами и лояльностью:** ведение базы посетителей с автоматическим расчетом прогрессивной скидки постоянного клиента.
* **Управление персоналом и СПА-зонами:** учет мастеров по специальностям и кабинетов специального назначения (хаммам, фитобочка, гидромассаж).
* **Складской контроль материалов:** учет масел, кремов и одноразовых принадлежностей, списание по технологическим картам и индикация критических остатков.
* **Файловая база данных:** надежное долговременное хранение всей информации в структурированных текстовых файлах (`.txt`).
* **Киллер-фича:** Интеллектуальный конструктор СПА-программ с многофакторным контролем ресурсных коллизий. Система не позволяет записать клиента, если мастер или кабинет уже заняты во времени, синхронно списывая необходимые расходники со склада.

## 🎓 Реализация технологических требований ООП

В проекте комплексно реализованы все обязательные темы курсового проектирования:
1. **Классы и объекты:** четкое разделение ответственности сущностей предметной области.
2. **Наследование и абстрактные классы:** базовый абстрактный класс `Person` с полиморфными наследниками `Client` и `Employee`.
3. **Виртуальные функции и динамический полиморфизм:** иерархия услуг `Service` $\rightarrow$ `SpaPackage` с переопределением расчета цены (`calculateCost`) и длительности (`getDuration`).
4. **Шаблоны классов (Templates):** обобщенное хранилище сущностей `Repository<T>`, инстанцируемое типами предметной области.
5. **Контейнеры STL и итераторы:** использование `std::vector`, алгоритмов сортировки `std::sort` и смарт-поинтеров `std::shared_ptr`.
6. **Перегрузка операторов и дружественные функции:**
    * `operator-=` для безопасного списания материалов со склада;
    * `operator<` для сортировки номенклатуры;
    * `operator==` для выявления коллизий расписания;
    * `friend operator<<` и `friend operator>>` для потокового ввода/вывода данных.
7. **Генерация и обработка исключений:** пользовательская иерархия ошибок `SpaException`, предотвращающая накладки записей и нехватку материалов.
8. **Потоки ввода/вывода (I/O Streams):** чтение и сохранение базы данных через `std::ifstream` и `std::ofstream`.

## 📁 Структура проекта

Проект разделен на интерфейсы (`include/`) и реализацию (`src/`) в соответствии с индустриальным стандартом C++:

```text
AuraSPA/
├── data/                       # Файловая база данных (.txt)
│   ├── clients.txt             # Клиенты и скидки
│   ├── employees.txt           # Мастера и ставки
│   ├── rooms.txt               # Кабинеты и СПА-зоны
│   ├── services.txt            # Услуги и пакеты
│   ├── inventory.txt           # Расходные материалы склада
│   └── appointments.txt        # Журнал записей
├── include/                    # Заголовочные файлы (.h)
│   ├── models/                 # Сущности (Person, Client, Room, etc.)
│   ├── core/                   # Шаблоны (Repository), исключения, FileManager
│   └── ui/                     # Заголовки окон Qt
├── src/                        # Исходный код (.cpp и .ui)
│   ├── models/                 # Реализация бизнес-сущностей
│   ├── core/                   # Реализация логики и файлов
│   ├── ui/                     # Логика и формы окон Qt Designer
│   └── main.cpp                # Точка входа в программу
├── CMakeLists.txt              # Конфигурация сборки CMake
└── .gitignore                  # Исключения для Git (CLion, CMake, Qt)
